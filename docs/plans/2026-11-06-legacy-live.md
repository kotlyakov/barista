## Контракт
`Repository.activate_legacy_candidate(expected_source_hash:String)->bool`, только обычный режим. Сверить актуальный строго прочитанный источник, канонический кандидат и полную резервную копию. Подготовить live-снимок с candidate_only=false в отдельном v2-activate, два валидных слота. Атомарно переименовать каталог вv2, только если назначения ещё нет. Затем reload. Никакой записи поверх существующего рабочего профиля.

Повтор с той же source_hash читает рабочий v2 без повторной компенсации/премии, даже после дальнейших трат/потери исходника. Другой hash отклоняется. При ошибке до публикации рабочий каталог отсутствует, деньги оригинала не меняются. Известное прерывание первой staging-записи (пустой каталог/только slot0.json.tmp) можно возобновить при подтверждённых источнике/кандидате/копиях; неизвестные/повреждённые файлы не удалять. Наличие v2-activate блокирует создание пустого нового профиля.

Schema принимает кандидат и активированную квитанцию, тип bool обязателен. Обычный Repository принимает только live false; review-mode не принимает оба варианта. Claim старой премии отсутствует в новой сессии — она уже входит в начальный кошелёк. Активация не встроена в нынешний UI, это043.
