# Интеграция 0.3.2 → ТЗ 0.4.2

**Goal:** внедрить свободное приготовление, независимых гостей и бесконечную карьеру с сохранением заработанного прогресса.
**Architecture:** сохранить Godot-проект и существующие Session/Repository/Store. Разделить рабочий стакан, визиты и платежи внутри локального снимка; не вводить сервер, ECS или универсальную шину событий.
**Tech Stack:** Godot 4.5.1.stable.official.f62fdbde1, GDScript, Android landscape, русский интерфейс.
**Spec:** `docs/GAME_SPEC.md` 0.4.2 и `docs/ROGUELIKE_SPEC.md`; SPEC-001/v5, MECH-001/v1, D10–D15 ACCEPTED.
**Base:** `42015e790eefd70c25808ac631da1a8d7ddc5351`, tip `task/TASK-029-gameplay-polish`, PR30; исходники прочитаны через GitHub. Локальный clone недоступен без Git-аутентификации; это не блокирует планирование и запись через подключённый GitHub. Последняя APK — 0.3.2; этот план не является внедрением.

## Общие ограничения

- Один рабочий стакан; ручной рецепт фиксируется первым засчитанным тапом. До пяти гостей, уникальных по customer_id.
- Единственный игровой отказ тапа аппарата — варка при grind_taps=0. Ввод во время паузы/переноса и второй палец обрабатываются отдельно.
- q=t/N до оптимума, затем max(0,1−(t−N)/10); счётчик продолжает расти после N+10. Минимальный N=1.
- Одна активная временная шкала для ожидания, температуры, пузырей, монет и смены; фон/меню замораживают её. Реальная дата не открывает новый день.
- День: 300 активных секунд, 08:00–17:00; максимум 15 секунд завершения готовки и оставшиеся сроки существующих платежей. База монет — 12 секунд, без автосбора.
- Новая смена не сбрасывает деньги, оборудование, L, отношения, настроение и историю. Нет финала на пятой смене/третьей жалобе.
- Старый HTML сохраняется только как свидетельство принятия механик. TASK-037 даёт новый визуал; новая графика/анимация/звук требуют отдельного решения владельца. Техническая заглушка не становится финальным оформлением.
- Стартовые значения из ТЗ отличаются от неподтверждённых цен/эффектов HTML. Speed combo остаётся выключенным до физической калибровки.

## Контракты новой модели

Ниже — технический проект API, не существующие функции. Поля снимка добавлять только в соответствующей задаче. Сохранить простые Dictionary и RefCounted.

| Сущность | Поля и ответственность |
|---|---|
| `cup` | id, выбранный recipe, targets[3], taps[3], first_tap, heat_start_level[2], heat_at[2], перенос; пустой стакан не связан с visit_id |
| `visits` | Массив максимум 5: id, customer_id, wish_recipe, state, patience_budget, arrived_at, bubble_until, departure_remaining, reaction_applied. Место занято до конца ухода |
| `payments` | id, visit_id, cup_id, amount/base/tip/combo, deadline, state=PENDING/COLLECTED/EXPIRED; отдельный ID от cup/visit |
| `profiles` | Существующие поля сохранить; добавить trust_l=0.5, историю C/J с маркером новой версии и цели/награды. relationship не переименовывать в L |
| `shift` | day_number, phase, elapsed, closing_remaining, event_id, offers[3], offer_decision, perk_id, effect_snapshot, summary_id, next_day_committed |
| `career` | owned_modules, equipped_modules<=2, gift reservations, fame, league, claimed_goal_ids; конкретный каталог — отдельная балансировка |
| Общее | clock, next_id, wallet (`money`), upgrades, preferences, rng_state. Сохранять RNG строкой, как сейчас |

Предлагаемые сигнатуры:
- Brew: `tap(station: int, now: float) -> bool`, `can_take() -> bool`, `temperature(now: float) -> float`, `snapshot() -> Dictionary`, `restore(data: Dictionary)`; индексы 0/1/2 — помол/варка/молоко, в том числе для эспрессо.
- Session: `select_recipe(recipe: String) -> bool` только для пустого стакана; `take_cup() -> bool`; `return_cup() -> bool`; `deliver(cup_id: int, visit_id: int) -> bool`; `collect(payment_id: int) -> bool`.
- Session: `spawn_visit() -> bool`, `remind_wish(visit_id: int) -> bool`, `advance(seconds: float, paused: bool=false) -> void`. Для движения добавить `finish_departure(visit_id: int) -> bool`, не удалять занятый слот при выдаче.
- Оценка в `brewing/evaluation.gd`: `evaluate(cup: Dictionary, wish_recipe: String, waited: float, patience: float, now: float) -> Dictionary` возвращает g/b/m/Q/d/T/W/R/J/C, фактический тип и дефекты; не пишет деньги/профили.
- Shift/Session: `start_shift() -> bool`, `finish_summary(summary_id: int) -> bool`; карьера: `buy_perk(offer_id: String, expected_day: int) -> bool`, `skip_perk(expected_day: int) -> bool`, `equip_module(module_id: String, slot: int) -> bool`. У Session операции идут через Repository.apply и один commit снимка.

Успешная выдача одной транзакцией закрывает стакан, обновляет конкретный визит/профиль/историю/серию, создаёт единственный платёж и пустой следующий стакан. Отображение/UI выполняются после успешного checkpoint. Старый cup_id или уже обслуженный/ушедший visit_id отклоняются. Ошибка записи откатывает всё, включая RNG и L.
