# Нативная основа — выполнение утверждённого плана

Вход: GAME_SPEC v0.3, main a5a0edb, утверждённый веб-визуал 09. Работать последовательно. Визуальные эксперименты не подменяют финальное утверждение. Стек: Godot 4.5.1/GDScript, Compatibility, Android landscape, JDK 17, SDK 35.

1. TASK-004: минимальный Godot-проект, main scene, headless smoke; шаблоны экспорта и Android debug export, команды и версии.
2. TASK-005: чистая модель приготовления; N−1/N/N+1/G, ручной переход, среднее всех обязательных этапов, отдельные дефекты; headless тесты.
3. TASK-006: технический UI приборов/полос; единый источник touch, один указатель, блокировка фона/паузы; автоматический тест ввода, проверка телефона отдельно.
4. TASK-007: один заказ, взятие/возврат/выдача, постоянные order_id/payment_id; повторы не меняют деньги; тесты.
5. TASK-008: два атомарных снимка, проверка/резерв, выдача и оплата сохраняются до UI; поломка файлов/перезапуски, настроение отдельно от отношения.
6. TASK-009: чаевые/серия/быстрый идеальный; формулы тестировать с подставным порогом. Боевой скоростной порог остаётся null до 10 попыток на телефоне по каждому рецепту. При необходимости ручной проверки не закрывать задачу; продолжать независимые работы.

Тесты пишутся и выполняются перед реализацией. Журнал: reports/native/PROGRESS.md. Коммиты/пуш после проверенных частей. Новые дефекты: BACKLOG.md. Перед остановкой — актуальные TASKS, PROJECT_STATE, HANDOFF. Непроверенное — NOT_RUN, не DONE.
