## 1. Что изменено по прямому указанию владельца
1. Попытка варить при нулевом помоле не засчитывается. Это единственный игровой отказ валидного тапа по аппарату в активном приготовлении.
2. Стакан доступен после первого засчитанного тапа ЛЮБОГО аппарата, включая молоко и кофемолку.
3. Одно молоко/один сухой помол имеют собственные состав и реплики.
4. Промах возвращает стакан в приготовление:его можно доделать.
5. Недотапы, перетапы, холод, ожидание и совпадение напитка участвуют в единой оценке с разным влиянием.
6. До пяти клиентов одновременно; игрок может обслуживать любого из них.
7. Терпение зависит от истории выпитого кофе и меняется после новых напитков.
8. Каждый произносит пожелание на3 активные секунды; пузыри не перекрываются. Напоминание —обычным тапом.
9. Нет глобального активного заказа, который выбирает рецепт/получателя за игрока. Пожелание каждого гостя остаётся данными для оценки соответствия.
Эти правила заменяют несовместимые предложения0.4:засчитывать варку целых зёрен, ждать первого тапа кофемашины для стакана, блокировать доработку после промаха, обслуживать только одного гостя и автоматически готовить его рецепт.
Остальные замечания05.11 (существующая рука,переработка графики,HUD,5-минутный день,усиления,баг эмоций) входят в эту рабочую редакцию;конкретные новые изображения/звук ещё не утверждены.

## 2. Рабочий стакан и тапы
Базовая модель:один рабочий стакан на стойке и до пяти независимых гостей. Несколько параллельных рабочих стаканов пока не добавляются автоматически; это отдельное расширение, которого владелец сейчас не требовал.

### 2.1. Когда засчитывается тап
- Тап по кофемолке всегда увеличивает счётчик помола рабочего стакана.
- Тап по капучинатору всегда увеличивает его молочную операцию и добавляет молочный компонент.
- Тап по кофемашине засчитывается только при grind_taps>=1; при grind_taps=0 бариста говорит «Ой! Зёрна-то не помолола!» и делает facepalm существующей рукой. Счётчик варки не растёт, кофе/новый стакан этим отклонённым тапом не создаются. Если уже было молоко, оно остаётся.
- После первого засчитанного тапа любой машины стакан можно брать. Это не утверждение, что содержимое уже вкусное или жидкое.
- К любой операции можно возвращаться до выдачи клиенту; идеальная шкала не обязательна.
- После N+10 тапы продолжают ЗАСЧИТЫВАТЬСЯ:счётчик растёт, шкала/вкус насыщаются на худшем уровне0. Поэтому правило «единственный отказ —целые зёрна» не нарушается старым cap.
- Ввод в меню/паузе, системная отмена, второй палец и синтетическая копия touch не являются игровыми тапами по рабочему стакану. Они не создают дополнительные действия.
- При переносе один активный палец держит стакан; операции продолжаются после его возвращения на стойку. Никакой скрытой зависимости «полностью закончить предыдущий прибор».

### 2.2. Состав и реплика
| Что реально сделано | Что в стакане | Реплика баристы при взятии |
|---|---|---|
| Только капучинатор, даже1 тап | Только молоко; его температура/пена соответствуют числу тапов | «Одно молоко!!!» |
| Только кофемолка, даже1 тап | Сухие молотые/раздробленные зёрна | «Тут же одни молотые зёрна!» |
| Помол есть,варки нет,молоко есть | Молоко с молотыми зёрнами,кофе не сварен | «Кофе-то не сварила!» |
| Помол и варка есть,молока нет | Кофейная часть | Нейтральная реплика по текущему состоянию;не объявлять молочный рецепт готовым |
| Помол,варка и молоко есть | Кофе с молочной частью | Реакция на реальный состав и дефекты |
Обычная короткая подсказка не обязана повторяться на каждое поднятие; одинаковую реплику ограничить cooldown. При выдаче получатель может сказать «Я же кофе просил!» на одно молоко. Реплика не блокирует выдачу.

### 2.3. Промах и доработка
При взятии создаётся только временный перенос, не окончательная фиксация вкуса. Счётчики, состав, накопленный перегрев и температурное состояние сохраняются.
Отпускание мимо всех клиентов →стакан возвращается на стойку→готовка снова доступна. Счётчики не сбрасываются, пропущенное молоко/варку можно добавить, недотапы довести, но перетапы вычитать нельзя.
Остывание продолжается при активной игре. Сам промах/поднятие не греет стакан. Настоящие новые тапы нагрева после возврата могут его нагреть и одновременно продолжают соответствующий счётчик/риск перетапа.
Вкус/получатель/температура/удовольствие фиксируются только при успешной выдаче. После неё этот стакан уже не исправляется; начинается новый пустой рабочий стакан, не связанный с конкретным гостем.
Центр стакана должен попасть в непересекающуюся актуальную зону выбранного гостя при отпускании. Между гостями —промах; не подбирать «ближайшего правильного» и не исправлять ошибку игрока автоматически.
Системная отмена и пауза возвращают стакан без выдачи и без блокировки дальнейшей доработки.

## 3. Как игрок выбирает, что готовит
Это новая существенная развилка, которой раньше не было из-за авто-рецепта заказа.
Игрок вручную выбирает задуманный рецепт для пустого рабочего стакана:эспрессо/капучино/латте. Выбор не привязан к нажатию на гостя и не меняется от показанного пожелания.
Нужна маленькая понятная настройка рецепта; конкретный вид ещё не утверждён и не рисуется в этой задаче. Не добавлять молча новые экраны.
Почему разделяются рецепт и тапы:14 тапов молока не должны автоматически превращать перетапанный капучино в идеальный латте. Тапы определяют качество, а выбранный рецепт —целевой состав/объём.
Цель рецепта фиксируется с первым засчитанным тапом; переключение названия уже приготовленного стакана не обнуляет порчу и не делает другой рецепт бесплатно.
Фактический состав важнее выбранного названия:молоко без кофе остаётся «молоко», сухой помол —«помол»; надпись «латте» сама по себе их не превращает в латте.
Для эспрессо без фактического молока критерий молока исключается. Если игрок всё же добавил молоко, оно учитывается как реальный компонент, влияет на качество/тип, а результат больше не является чистым эспрессо.
Сохраняется прежняя стартовая калибровка:N помола12,варки16,молока10 для капучино/14 для латте. Для случайно добавленного молока в эспрессо принят стартовый N=10. Это калибровочное значение рабочей редакции.

### 3.1. Однозначная классификация для R
| Фактические компоненты | Выбранный рецепт | Что выдано | R при пожелании клиента |
|---|---|---|---|
| Есть варка,нет молока | Любой | Эспрессо/кофейная часть | 1 для эспрессо;0.5 для капучино/латте |
| Есть варка и молоко | Капучино | Капучино | 1 для капучино;0.5 для других кофейных рецептов |
| Есть варка и молоко | Латте | Латте | 1 для латте;0.5 для других кофейных рецептов |
| Есть варка и молоко | Эспрессо | Кофе с непредусмотренным молоком | 0.5 для любого из трёх кофейных пожеланий |
| Только молоко,варки нет | Любой | Молоко | 0 для любого кофейного пожелания |
| Помол и молоко есть,варки нет | Любой | Молоко с сырым помолом | 0 для любого кофейного пожелания |
| Только помол,варки нет | Любой | Сухие молотые зёрна | 0 для любого кофейного пожелания |
Варка означает brew_taps>=1,а не q_b>0;перетапанный до q_b=0 напиток всё ещё содержит кофе. Рецепт определяет целевой состав/объём,а не автоматически количество эффективных ингредиентов.
Q оценивает выполнение выбранной игроком технологии и реальные добавленные компоненты;R —соответствие фактически выданного клиенту. Например,капучино без молока получает q_m=0 и классифицируется как кофейная часть:клиент эспрессо получает R=1,клиент капучино R=0.5. Совмещение штрафов недостающего обязательного компонента в Q и несоответствия в R здесь зафиксировано намеренно и явно,не является скрытым правилом реализации.
Чистое молоко как отдельное пожелание гостя пока не добавляется:сохраняются три кофейных рецепта. Позже набор пожеланий можно расширить отдельно.

## 5. Формула:каждый критерий влияет по-разному
Обозначения:g=q_g —качество помола,b=q_b —варки,m=q_m —молока,T —температурный комфорт,W —удовлетворённость ожиданием,R —совпадение с пожеланием. Это оценки0..1,не счётчики. Число тапов хранится отдельно как grind_taps/brew_taps/milk_taps. Условие разрешения варки проверяет только grind_taps>=1,даже если от сильного перетапа q_g уже стало0.
Для напитка с молочным критерием:
Q = 0.25*g + 0.45*b + 0.30*m.
Для чистого эспрессо без молока:
Q = (0.25*g + 0.45*b)/0.70.
Молочный критерий включается,если молоко требуется задуманным рецептом ИЛИ реально добавлено. Так плохое случайное молоко не исчезает из расчёта под названием «эспрессо».
d —минимальное q среди учитываемых этапов. Оно применяется как дополнительный штраф сильного дефекта,а не подменяет Q минимумом.
W = clamp(1 - waited_seconds/patience_budget,0,1).
R=1 —точное соответствие;R=0.5 —другой кофейный рецепт;R=0 —другой класс содержимого (молоко/сухой помол вместо кофе). Это стартовые коэффициенты рабочей редакции.
Удовольствие:
J = 100*(0.85*Q + 0.15*W)*(0.20 + 0.80*R)*(0.25 + 0.75*T)*(0.40 + 0.60*d).
J ограничено0..100. Вес варки больше веса молока,а молока —помола;ожидание мягче вкуса,но температура/ошибка напитка/сильный дефект имеют отдельные штрафы. Вклад каждого этапа остаётся положительным:хорошие остальные этапы улучшают результат,но не скрывают испорченный компонент.
Производная модель «качество напитка» —Q;окончательные мимика/реплика/история удовольствия/право на чаевые используют J и конкретные дефекты. Не выбирать улыбку отдельно только по Q.
Примерные границы реакции:J>=90 —восторг;75–89 —доволен;60–74 —спокойно;40–59 —разочарован;20–39 —сильно недоволен;0–19 —отвращение. Это стартовые пороги;точные лица утверждаются отдельно.
Правила оплаты/чаевых не менять молча:сохраняется существующая базовая оплата и перенести проверку хорошего обслуживания на J>=75;серия/лояльность остаются условиями права на чаевые. Идеальный скоростной бонус требует правильного рецепта,идеальных учитываемых этапов,максимального температурного комфорта и откалиброванной скорости. Прочие штрафы/отказ платить —отдельное продуктовое решение,не часть этого документа.

## 6. Пять клиентов и ажиотаж
- Одновременно максимум5 клиентов,у каждого свои пожелание,терпение,мимика,фаза движения,оплата и постоянный профиль.
- Новый гость может прийти,пока предыдущие ждут. Никакого требования «сначала обслужить текущего».
- Высокий игровой прогресс/реклама увеличивают поток. Медленная работа и терпеливые гости приводят к накоплению ожидающих.
- Стартовый интервал потока:A(day)=clamp(16/(1+0.12*(day-1)),6,16) активных секунд;новый интервал выбирается в0.75A..1.25A. Реклама модифицирует отдельно. Это стартовая калибровка для плейтеста.
- При пяти занятых местах шестой клиент не появляется на сцене и не образует скрытую бесконечную очередь. Следующая возможность входа проверяется после освобождения места.
- Место занято до завершения ухода,а не только до получения кофе. Вход/выход и сдвиг очереди сохраняют дистанцию,не пересекают фигуры/стойку.
- Один и тот же герой не появляется на сцене дважды одновременно. Профиль героя и ID конкретного визита различаются;перестановка гостей не меняет их пожелания/оплату.
- Игрок выдаёт первому,последнему или любому в середине. Отдельного штрафа «не по очереди» нет:остальные теряют терпение от фактического ожидания. Это заменяет старое ожидание строгой очередности.
- Пожелание не является активным системным заказом. Это приватные данные гостя,с которыми сравнивается вручную приготовленное содержимое при выдаче.

## 7. История кофе и динамическое терпение
Для героя сохраняется L в0..1 —доверие к качеству выпитых напитков. Начальное L=0.5.
После каждого выпитого напитка:
C = Q*(0.20+0.80*R)*(0.25+0.75*T)*(0.40+0.60*d)
L_next = clamp(0.75*L + 0.25*C,0,1).
C оценивает выпитый кофе,а не ожидание. Поэтому ожидание не ухудшает вкус в истории и не создаёт двойной круг снижения терпения. J отражает всё впечатление текущего посещения,включая ожидание.
Лимит терпения следующего визита:
P = 30 + 90*L секунд.
При L=0 —30с,при0.5 —75с,при1 —120с. После четырёх идеальных горячих правильных напитков L≈0.842,P≈106с;после четырёх максимально плохих L≈0.158,P≈44с. Это стартовые пределы рабочей редакции.
Во время ожидания оставшееся время уменьшается непрерывно,мимика постепенно переходит от спокойствия к нетерпению. Бюджет P фиксируется при входе;его не пересчитывают каждый кадр так,чтобы он незаметно продлевал сам себя.
Обновление L выполняется один раз при оценке выданного напитка;не повторяется при сборе монет,исчезновении пузыря/перезапуске. Уход без напитка меняет настроение посещения,но не подделывает историю выпитого кофе:сам L от несуществующего напитка не обновляется.
Хорошие напитки постепенно делают героя терпеливее,плохие/холодные/неправильные —постепенно менее терпеливым. Одна ошибка не стирает всю хорошую историю.
Доверие,отношение,настроение и история сохраняются по постоянному customer_id;их нельзя случайно обнулить при каждом появлении героя. Связь L с существующим relationship при миграции требует явного правила,а не автоматического переиспользования другого диапазона.

## 8. Пожелания,пузыри и свободная выдача
Каждый подошедший гость произносит пожелание на3 активные секунды. Затем пузырь пропадает,а желание сохраняется.
Тап по ожидающему клиенту повторяет пожелание на3 секунды;не выбирает рецепт рабочего стакана,не назначает обязательного получателя и не продлевает терпение.
До пяти пузырей одновременно раскладываются без пересечений друг с другом,лицами,верхней панелью,монетами и зонами выдачи. Разрешены несколько рядов/смещение в свободное пространство;хвост ведёт к рту своего персонажа. Не прятать один пузырь под другим и не укорачивать его3 секунды из-за коллизии.
Слова/реплики баристы и реакции клиента —исчезающие комиксные пузыри. Короткое имя может быть внутри пузыря пожелания. Числовые HUD/кнопки остаются системным интерфейсом.
Зоны гостей не пересекаются. Получатель определяется по фактической зоне в момент отпускания,а не по последнему показанному пузырю. Тап на монеты имеет приоритет над напоминанием пожелания. Drag/второй палец/отмена не вызывают повтор пожелания.
Получивший напиток реагирует на J/конкретные дефекты/совпадение;пожелание считается удовлетворённым попыткой обслуживания,даже если игрок ошибся. Он не становится новым обязательным заданием на исправление.
Платёж создаётся один раз у соответствующего гостя;несколько гостей могут иметь отдельные монеты. Ровно один сбор каждого payment_id,прежний срок исчезновения монет и отсутствие автоначисления сохраняются. Монеты/пузыри не перекрываются;таймеры стоят на паузе в меню/окне усилений.

## 9. Температура,пар и возврат
Сохраняются10 уровней пара проекта0.4:уровень1 горячий,на10 пар отсутствует/напиток полностью остыл. Базовый шаг1 активная секунда даёт9с от1 до10. T=(10-L)/9,где L —уровень;от1 до0.
Компоненты кофе и молока имеют отдельные нагрев/таймеры. Недогрев стартует со слабого пара,а не обязательно с уровня1.

Для каждого компонента i∈{кофе,молоко} действует правило:
- До первого засчитанного тапа его нагрев равен0,уровень L_i=10.
- Каждый засчитанный тап соответствующего нагревающего аппарата задаёт h_i=clamp(taps_i/N_i,0,1),L_i_start=clamp(10-ceil(9*h_i),1,10) и сохраняет момент heat_at_i по активным часам.
- В последующие моменты L_i=min(10,L_i_start+floor((active_clock-heat_at_i)/1сек)).
- q_i после перетапа может падать,но h_i определяется нагревом,поэтому горячий испорченный напиток остаётся горячим. Все засчитанные тапы после N+10 всё ещё могут нагревать,не возвращая качество.
- Для молока без кофе L=L_молоко;для кофе без молока L=L_кофе;если оба компонента реально есть,L=min(L_кофе,L_молоко). Сухой помол без жидкости имеет T=0.
- T=(10-L)/9. Это явно игровое объединение по более горячему компоненту,без физического расчёта смешивания.
Оба компонентных состояния/таймера сохраняются при поднятии,переносе,возврате и загрузке. Взятие стакана не объединяет их с потерей данных и не обнуляет долю секунды. Выдача сохраняет снимок T для оценки выпитого напитка.

Тапы нагрева после возврата стакана могут повысить температуру;счётчики при этом не обнуляются. До N новые тапы исправляют недобор,после N углубляют перетап. Качество пересчитывается по сохранённым новым счётчикам. Поднятие/возврат/промах сами температуру не повышают.
При переносе сохраняются температура/остаток интервала. При промахе состояние возвращается без перезапуска остывания и доступно для дальнейшего приготовления. При успешной выдаче фиксируется именно температура момента выдачи.
Пауза/фон/окно усилений замораживают все активные таймеры. Скорость часов игрового дня не меняет скрыто сроки монет/пара/терпения.

Между сменами доступны итог/прогноз события, покупка одного из трёх усилений на день или пропуск, постоянные улучшения приборов, два устанавливаемых модуля, личные цели и угощения постоянникам, добровольное повышение лиги известности. Сложность растёт через поток до5 гостей и сочетания событий/пожеланий;у игрока есть возможности подготовиться и улучшиться.
Тяжёлая смена влияет на доход/отношения,но не обнуляет карьеру. Законченный забег из5смен и прекращение после3жалоб не действуют. Старое D03 «одна смена=забег» заменено D15. При этом сама смена/итог остаются.
Полные правила и границы одобрения:docs/ROGUELIKE_SPEC.md;короткие тексты:docs/PLAYER_MECHANICS.md. Цены/проценты/количество лиг из примера —стартовые иллюстрации для отдельной балансировки,не окончательные значения.
