## Начальная загрузка и дальнейшая работа
Первичная инициализация пустого репозитория выполняется непосредственно в main (bootstrap).
Это исключение только для начального пакета; последующие изменения — task-ветки и PR.
Фактический remote: https://github.com/kotlyakov/barista.git.
Поле repository.head в состоянии означает последний наблюдавшийся проверенный SHA;
коммит не может содержать собственный SHA, поэтому он может быть предком текущего HEAD.
GitHub Actions docs-check добавляется с пакетом. Наличие файла workflow не доказывает запуск.
Статус CI проверяется отдельно; при недоступности инструмента фиксируется NOT_VERIFIED.
Защита ветки рекомендуется ниже, но этим пакетом не включается автоматически.

## Рабочий процесс
- main содержит только проверенную интегрированную работу. На задачу ветка task/TASK-XXX-name и PR.
- TASK-ID присутствует в коммите, PR и Issue; один результат задачи на PR, кроме документированного объединения.
- При создании Issues переносить точные критерии из TASKS.json; сохранять issue_number обратно.
- Не путать роль ИИ с GitHub-пользователем; не назначать реального человека без основания.
- Статусы задач живут в TASKS.json; Issues отражают их. Новую задачу сначала оформить в реестре.
- Ревью проверяет поведение, зависимости, утверждения и доказательства. Настройки защиты ветки соблюдать.
- Рекомендуемые правила main: запрет force-push, проверка docs-check, PR перед слиянием. Их фактическое включение зависит от доступа/тарифа.
- CI сначала проверяет документацию. После TASK-004 добавить реальные build/test jobs на зафиксированной версии движка.
- Перед merge актуализировать main, разрешить конфликты и повторить затронутые проверки. При проверках зелёного старого HEAD не сливать новый непроверенный.
- После merge обновить task commit/PR/status и next_action. Если sync не удался, записать pending_sync, не дублировать Issues вслепую.
- Контрольные APK выпускать как versioned prerelease с commit SHA, краткими изменениями и ограничениями.
- Платную инфраструктуру/публичность/доступы не включать автоматически. Исходники закрыты, пока владелец не выбрал лицензию.
