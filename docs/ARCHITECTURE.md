# Предварительная архитектура — зависит от D01
Не создавать эти игровые файлы до фиксации стека. Ниже предложены ответственность и контракты, не готовый API движка.

| Область | Ответственность | Предлагаемый путь после выбора Godot |
|---|---|---|
| Приготовление | Количество тапов, этап, качество, готовность | game/brewing/ |
| Заказ | Рецепт, клиент, выдача, активное время, payment_id | game/orders/ |
| Клиенты | Профили, отношение, взвешенный выбор | game/customers/ |
| Экономика | Кошелёк, чаевые, улучшения, защита повторного начисления | game/economy/ |
| Смена | day_key, состояние магазина/смены/итога | game/shift/ |
| Сохранения | Версия схемы, атомарная запись, восстановление | game/persistence/ |
| Интерфейс | Тап-зоны, drag/drop, полосы и подсказки | game/ui/ |
| Контент | Рецепты, баланс, герои, утверждённые ресурсы | game/content/ |
| Проверки | Детерминированные сценарии домена и ввод/сохранение | game/tests/ |

## Концептуальные контракты
- tap(station_id, pointer_event_id) → operation_progress/quality; дедупликация ввода на границе UI.
- switch разрешён только после порога текущей обязательной операции; первый тап следующей учитывается.
- deliver(order_id, customer_id) → payment_id либо отказ; повторная выдача идемпотентна.
- collect(payment_id) → изменение кошелька максимум один раз.
- purchase(upgrade_id, transaction_id) → баланс+уровень, атомарно.
- get_day_key(wall_time, zone, boundary=08:00); timer использует независимые монотонные часы.
- snapshot(schema_version) хранит незавершённый заказ, платёж, RNG/seed, кошелёк, смену и отношения.

Отделить вычисления от UI ровно настолько, чтобы проверять операции и деньги без кликов.
Не вводить микросервисы, сетевой backend, собственную ECS или универсальный event bus без измеренной необходимости.
Техлид TASK-004 фиксирует реальные типы, enum, версии и команды в docs/BUILD.md; исполнители не угадывают API.
Контракт меняется через запись решения и согласование зависимых задач; не ломать интерфейс другой ветки молча.
